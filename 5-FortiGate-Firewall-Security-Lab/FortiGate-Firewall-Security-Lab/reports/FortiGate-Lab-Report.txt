FortiGate Firewall & Security Profiles Lab Report
====================================================
Author: Bishoy Hany
Device: FortiGate VM64 "FW1", firmware v7.6.7

1. PROJECT OVERVIEW
---------------------
This lab focused on configuring a FortiGate next-generation firewall to
control traffic between an internal LAN and the WAN, then layering
seven security profiles on top of that base policy to inspect traffic
more deeply.

2. PART 1 - INTERFACES & FIREWALL POLICY CONFIGURATION
------------------------------------------------------------
Steps performed:
- Logged into the FortiGate GUI
- Reviewed interfaces under Network > Interfaces: LAN (port2,
  192.168.2.1/24), WAN (port1, 90.1.1.129/24), DMZ (port3, 192.168.3.1/24)
- Navigated to Policy & Objects > Firewall Policy
- Created a new policy named "LAN to WAN" (Policy ID 1)
- Set incoming interface to LAN (port2), outgoing interface to WAN (port1)
- Configured source (PC1, users) and destination (all) objects
- Set action to ACCEPT, service to ALL, inspection mode to Flow-based
- Enabled NAT (Use Outgoing Interface Address, source port translation
  "When port conflicts") so internal hosts can reach external networks
- Enabled logging of allowed traffic (Security events)
- Tested connectivity from a Windows client using ping

Outcome: Internal hosts successfully reached external destinations
through the LAN-to-WAN policy. Policy statistics confirmed an active
hit count and traffic volume, validating correct interface, NAT, and
action configuration.

3. PART 2 - SECURITY PROFILES CONFIGURATION
----------------------------------------------
Steps performed:
- Configured a custom AntiVirus profile (flow-based, HTTP/SMTP/POP3/
  IMAP/FTP/CIFS inspected, mobile malware protection enabled)
- Configured a custom Web Filter profile (FortiGuard category filtering,
  Safe Search enforced, YouTube restricted to Moderate)
- Configured a custom DNS Filter profile (category-based filtering,
  botnet C&C redirect, Safe Search enforced, Strict YouTube restriction)
- Configured a custom Application Control sensor covering all major
  categories, with an override blocking the Facebook application
- Configured a custom IPS sensor with server/client signatures across
  severity levels
- Created a custom File Filter profile matching HTTP/FTP (and other)
  protocols, selected file types (7z, bat, and others), action Monitor
- Configured a custom SSL/SSH Inspection profile (deep inspection) with
  trusted-site exemptions (Finance and Banking, Health and Wellness
  categories, plus named services such as Google, Microsoft, Apple, and
  Dropbox) and strict handling of expired/revoked/invalid certificates
- Reviewed how each profile attaches to and works with the LAN-to-WAN
  firewall policy created in Part 1

Outcome: Traffic passing through the LAN-to-WAN policy is now inspected
across multiple layers (antivirus, web, DNS, application, intrusion,
file type, and SSL/SSH), rather than being simply allowed or denied.

4. TESTING & VALIDATION
--------------------------
- Used Windows Command Prompt (ping) to confirm connectivity after each
  major configuration change
- Reviewed FortiGate policy statistics (hit count, active sessions,
  total bytes, bandwidth graph) to confirm the policy was actively
  processing traffic

5. WHAT I LEARNED
---------------------
- How a firewall evaluates traffic against policies in order
- How NAT enables internal-to-external communication
- How security profiles add layered defense beyond basic allow/deny
  rules
- How SSL/SSH deep inspection and certificate validation settings
  affect encrypted traffic handling
- How to validate firewall configuration changes with real connectivity
  tests and policy statistics review
